Purpose of the Model

The Open Systems Interconnection model separates network communication into seven conceptual layers. This makes complex communication easier to explain and troubleshoot because each layer has a defined purpose.

The OSI model is primarily an analytical framework, whereas operational internet systems use the TCP/IP protocol suite. During transmission, information moves from the application layer towards the physical layer. The receiving system processes the information in the opposite direction (Kurose and Ross, 2021).

Layer-by-Layer Troubleshooting

Layer Main purpose Example failure
7. Application Provides network functions directly used by software applications. A web server returns an application error.
6. Presentation Ensures data is represented in an agreed format. Sender and receiver use incompatible character encodings.
5. Session Coordinates ongoing communication between applications. A session expires or is unexpectedly terminated.
4. Transport Delivers data between application processes and manages ports. A firewall blocks the required TCP port.
3. Network Routes packets using logical addresses. An incorrect route prevents packets reaching another network.
2. Data Link Moves frames between devices on the same local network. A switching or VLAN configuration is incorrect.
1. Physical Carries signals through the transmission medium. A damaged cable prevents any connection.

Encapsulation

Encapsulation occurs when protocol layers add headers, and sometimes trailers, as data moves down the network stack. The destination interprets and removes the corresponding information as the data moves upwards (Stallings, 2020).

Application Data User or application content
Transport Segment TCP or UDP information is added
Network Packet Source and destination IP addresses are added
Data-Link Frame Local delivery information is added
Physical Bits Data is transmitted as signals

Example

An HTTP request may be carried inside a TCP segment. The segment is placed inside an IP packet, and the packet is placed inside an Ethernet or Wi-Fi frame.

OSI and TCP/IP Comparison

The OSI model is more detailed and is widely used for teaching and troubleshooting. TCP/IP more closely represents the protocol suite used by operational internet systems. Protocols such as TLS and QUIC can span boundaries that simplified diagrams may imply are rigid.

Critical Evaluation

Strength

The model provides a common vocabulary for describing network functions and faults.

Limitation

Modern protocols do not always fit neatly into a single layer and may perform functions across several layers.

Practical Use

The model should guide diagnosis and explanation without being treated as a rigid description of every implementation.
