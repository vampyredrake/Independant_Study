Search Algorithm Comparison

Linear Search and Binary Search

Overview

Searching algorithms locate a target value within a collection. Linear search prioritises simplicity and flexibility, while binary search prioritises efficiency but requires ordered data and suitable indexed access (Cormen et al., 2022).

Comparison Table

Characteristic Linear Search Binary Search
Data order Works with sorted or unsorted data. Requires sorted data.
Method Checks each item sequentially. Repeatedly halves the search area.
Best case O(1) O(1)
Average case O(n) O(log n)
Worst case O(n) O(log n)
Implementation Simple. More complex.
Suitable structures Arrays, lists and sequential data. Sorted arrays or structures with fast indexing.

Linear Search 

FUNCTION linearSearch(items, target)

    FOR each position in items

        IF items[position] equals target
            RETURN position

    RETURN not found

Linear search is appropriate where the dataset is small, unsorted or searched only occasionally. Sorting a collection purely to perform one search may cost more than checking the items sequentially.

It is also suitable for linked lists because moving directly to a middle position is not efficient in a linked structure.

Binary Search 

FUNCTION binarySearch(items, target)

    low = 0
    high = length of items - 1

    WHILE low is less than or equal to high

        middle = floor((low + high) / 2)

        IF items[middle] equals target
            RETURN middle

        IF items[middle] is less than target
            low = middle + 1

        ELSE
            high = middle - 1

    RETURN not found

Binary search becomes valuable when the collection is large, sorted and searched repeatedly. Each comparison eliminates approximately half of the remaining values.

For a collection containing approximately one million sorted items, binary search requires around twenty comparisons in the worst case because each comparison halves the remaining range. Linear search may require close to one million comparisons. This comparison shows the difference in growth rate, but not the cost of first sorting the data or maintaining its order.

Evaluation

Binary search has better asymptotic performance, but it is not automatically the correct choice. The cost of sorting and maintaining order must also be considered. Wengrow (2020) argues that algorithm selection should follow the real use case: a theoretically faster search can still be inefficient if its prerequisites are costly or rarely reused.

A small unsorted collection searched once is likely to favour linear search. A large sorted index searched many times is likely to favour binary search.

The underlying data structure also matters. Binary search is efficient on an array because the middle element can be accessed directly. On a linked list, locating the middle element requires traversal, reducing the benefit.
