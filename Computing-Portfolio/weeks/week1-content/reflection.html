Critical Reflection

Before completing this study, I tended to separate web development into front-end code and back-end code. The most significant change in my understanding is that a web application should be viewed as one connected system. Semantic HTML, JavaScript behaviour, DNS resolution, HTTPS communication and server-side processing all influence the user's experience, even though many of these stages are not visible.

The client-server request lifecycle was particularly useful because it gave context to technologies I had previously studied individually. DNS is not simply an internet definition to remember; it is the stage that allows the browser to locate the server. HTTPS is also more than displaying a padlock. TLS protects information while it moves between the client and server and helps confirm that the browser is communicating with the intended service. This has made security feel more closely connected to everyday development decisions.

I also found the comparison between dynamic and strongly typed approaches significant. JavaScript's flexibility supports rapid development, but it can allow type-related problems to remain hidden until runtime. Strong typing can detect more problems earlier and make large codebases easier to understand, although it introduces additional structure. This suggests that technology choice should depend on project scale and risk rather than personal preference.

These concepts relate directly to professional software development because maintainability depends on decisions made across the whole system. Semantic structure can support accessibility, but WCAG 2.2 shows that accessible design also depends on operability, clarity and robustness (World Wide Web Consortium, 2023). Suitable architecture can support growth and controlled programming techniques can reduce defects. However, adding complexity without a clear requirement can make a system harder to maintain. The area I need to investigate further is asynchronous programming and concurrency, particularly how race conditions occur and how developers test systems where several tasks may interact with the same data.

Reflection Summary

Most significant concept: understanding a web application as a connected system.

Professional relevance: architecture, accessibility, security and maintainability influence one another.

Further investigation: asynchronous behaviour, shared state and concurrency testing.
