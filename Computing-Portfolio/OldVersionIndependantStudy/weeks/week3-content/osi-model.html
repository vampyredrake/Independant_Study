Purpose of the Model

The OSI model separates network communication into seven conceptual layers. This makes complex communication easier to explain and troubleshoot because each layer has a defined purpose. It is primarily an analytical model, whereas the internet is implemented through the TCP/IP protocol suite (Kurose and Ross, 2021).

During transmission, information moves from the application layer down toward the physical layer. Receiving systems process the information in the opposite direction.

Labelled OSI Diagram

Layer 7: Application

Provides network services used by applications.

Examples: HTTP, HTTPS, DNS, SMTP and FTP

Data unit: Data

Layer 6: Presentation

Translates data formats and may perform encryption, decryption and compression.

Examples: character encoding, image formats and encryption formats

Data unit: Data

Layer 5: Session

Establishes, manages and terminates communication sessions between applications.

Examples: session control, checkpoints and dialog management

Data unit: Data

Layer 4: Transport

Provides end-to-end communication, segmentation, ports, reliability and flow control.

Examples: TCP and UDP

Data unit: Segment or datagram

Layer 3: Network

Provides logical addressing and routing between different networks.

Examples: IPv4, IPv6, ICMP and routers

Data unit: Packet

Layer 2: Data Link

Transfers frames across a local network and uses hardware addresses for local delivery.

Examples: Ethernet, Wi-Fi, MAC addresses and switches

Data unit: Frame

Layer 1: Physical

Transmits raw bits using electrical, optical or wireless signals.

Examples: cables, connectors, radio signals and network interface hardware

Data unit: Bits

Layer-by-Layer Explanation

Layer Main Purpose Example Failure
7. Application Provides network functions directly used by software applications. A web server returns an application error.
6. Presentation Ensures data is represented in an agreed format. The sender and receiver use incompatible character encodings.
5. Session Coordinates ongoing communication between applications. A session expires or is unexpectedly terminated.
4. Transport Delivers data between application processes and manages ports. A firewall blocks the required TCP port.
3. Network Routes packets using logical addresses. An incorrect route prevents packets reaching another network.
2. Data Link Moves frames between devices on the same local network. A switching or VLAN configuration is incorrect.
1. Physical Carries signals through the transmission medium. A damaged cable prevents any connection.

Encapsulation

Encapsulation occurs when protocol layers add headers, and sometimes trailers, as data moves down the network stack. At the destination, the corresponding information is interpreted and removed as the data moves upward. This abstraction is useful, although real implementations may combine functions that the OSI model separates (Stallings, 2020).

For example, an HTTP request is carried inside a TCP segment. The segment is carried inside an IP packet, and the packet is carried inside an Ethernet or Wi-Fi frame.

OSI and TCP/IP Comparison

OSI Model TCP/IP Model
Application, presentation and session Application
Transport Transport
Network Internet
Data link and physical Network access

The OSI model is more detailed and is widely used for teaching and troubleshooting. TCP/IP more closely represents the protocol suite used by operational internet systems. The mapping is therefore approximate: protocols such as TLS and QUIC cross boundaries that a simplified layer diagram may imply are rigid.

Critical Evaluation

The OSI model is useful because it provides a common vocabulary. A technician can describe a problem as physical, transport or application related without first explaining the entire system. Its value is diagnostic rather than predictive: assigning a fault to one layer does not prove that dependencies at other layers are functioning correctly.

Its limitation is that modern protocols sometimes span several layers. TLS, for example, performs functions associated with presentation security but operates alongside application and transport protocols.

The model should therefore guide analysis without being treated as a rigid description of every network implementation.
