Assessment Approach

This analysis focuses on threats that are less commonly selected than standard examples such as ransomware, ordinary password phishing or generic malware.

Likelihood is expressed qualitatively as low, medium or high. These ratings are comparative judgements rather than statistical probabilities. The actual likelihood for an organisation depends on its systems, suppliers, exposure, threat intelligence and existing controls. NIST CSF 2.0 recommends that cybersecurity outcomes are prioritised in relation to organisational context and risk (National Institute of Standards and Technology, 2024).

1. Cloud Metadata Service Exploitation

Cloud virtual machines may use a metadata service to obtain configuration information and temporary credentials. This service is intended to be accessible from the workload rather than the public internet.

A vulnerable application may allow an attacker to make requests from the server. This is known as server-side request forgery. The attacker may direct the server toward its metadata service and attempt to obtain cloud credentials.

The seriousness depends on the permissions attached to the workload. A narrowly restricted role may limit the damage, whereas an overprivileged role could allow access to storage, secrets or additional services. AWS recommends controls such as IMDSv2 and limiting metadata access, but secure configuration must be combined with protection against server-side request forgery (Amazon Web Services, 2026).

2. Dependency Confusion

Modern applications rely on packages from public and private repositories. Dependency confusion occurs when a package manager retrieves an attacker-controlled public package instead of the intended internal package.

The attacker selects a name matching an organisation's private dependency and publishes a package with a version number or configuration likely to be preferred by the package-management process.

This threat is significant because malicious code may execute inside trusted development or build infrastructure. It may therefore access source repositories, signing keys, environment variables or deployment credentials. A software bill of materials can improve component visibility, but it does not establish that a component is trustworthy or uncompromised (Cybersecurity and Infrastructure Security Agency, 2021).

3. OAuth Consent Phishing

OAuth consent phishing does not always require an attacker to obtain a user's password. The user is persuaded to authorise a malicious application to access cloud information.

A user may see a legitimate provider login page followed by a request for permissions. If those permissions are approved, the application may receive tokens that allow continuing access.

Conventional password changes may not remove the malicious application's permission. Organisations must therefore monitor application consent and revoke unauthorised tokens or applications. Restricting user consent and requiring administrative approval for high-risk permissions reduces exposure, although it also creates an approval workload that must be managed effectively (Microsoft, 2026).

4. BGP Route Hijacking

Border Gateway Protocol is used to exchange routing information between large networks. A route hijack occurs when incorrect route information causes traffic to travel toward an unauthorised network.

Some incidents are accidental, while others may be deliberate. The result can include traffic disruption, interception or redirection.

RPKI and route-origin validation can help networks verify whether an autonomous system is authorised to originate a particular address range. These controls reduce invalid route announcements but do not prove that every accepted path is safe. TLS also reduces the value of intercepted traffic because communication remains encrypted and authenticated when correctly configured (Internet Engineering Task Force, 2018).

5. Domain Shadowing

Domain shadowing occurs when attackers obtain access to a legitimate domain-management account and create unauthorised subdomains. The original website may remain unchanged, making the compromise less obvious.

The malicious subdomains benefit from the reputation of the legitimate parent domain. They may be used for phishing or malware delivery until detected.

Monitoring DNS changes and certificate issuance can help identify unexpected domain activity. Registrar accounts should be protected as privileged systems through strong authentication, restricted administration and verified recovery procedures. Monitoring is detective rather than preventive, so rapid ownership and incident-response processes remain necessary.

6. Hypervisor Escape

Virtual machines depend on the hypervisor to maintain isolation. A hypervisor-escape vulnerability could allow code inside a guest virtual machine to reach the host or another guest.

These attacks are relatively uncommon because they normally require a specific vulnerability and technical conditions. The potential impact is severe because the virtualisation layer may support several important systems.

Isolation should therefore be combined with patching, workload separation and strong administrative controls.

Overall Evaluation

The selected threats show that modern attacks often target trust relationships rather than only individual devices. Cloud roles trust workloads, build systems trust package repositories, users trust consent screens and networks trust routing announcements.

Controls must therefore validate where requests, identities, software and network information originate. Monitoring is also necessary because preventative controls cannot remove every risk.
