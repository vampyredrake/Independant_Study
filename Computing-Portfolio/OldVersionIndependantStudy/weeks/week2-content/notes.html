Introduction

Software systems depend on data being organised in a form that supports the operations they need to perform. A suitable data structure can make searching, insertion and removal efficient, while an unsuitable choice can create unnecessary processing and memory costs.

Algorithms must also be evaluated according to how their behaviour changes as the amount of data increases. Cormen et al. (2022) show that asymptotic analysis allows algorithms to be compared independently of a particular machine. Performance should therefore be considered during software design, while later profiling should confirm whether the theoretical model reflects the real workload.

1. Data Structures

Stacks

A stack follows the Last In, First Out principle. The most recently added item is the first item removed. Adding an item is commonly called a push operation, while removing the top item is called a pop operation.

Stacks are used for undo systems, function calls, browser history and expression evaluation. Their main limitation is that only the top item is directly accessible. 

stack = []

stack.append("Page 1")
stack.append("Page 2")

current_page = stack.pop()

Queues

A queue follows the First In, First Out principle. The first item added is the first item processed. Queues are suitable where tasks should normally be handled in the order they arrive.

Examples include print queues, customer-service systems, message processing and job scheduling. Priority queues modify the basic rule by allowing more urgent tasks to be processed first.

Linked Lists

A linked list contains nodes. Each node stores a value and a reference to another node. In a singly linked list, each node points to the next node. In a doubly linked list, each node also points to the previous node.

Linked lists support efficient insertion and deletion when the relevant node is already known. However, they do not provide direct indexed access. To reach a later item, the program must normally move through earlier nodes. Wengrow (2020) emphasises that the practical value of a structure depends on the operations performed most frequently, rather than on one isolated complexity measure.

Binary Search Trees

A binary search tree stores values in nodes with no more than two children. Values smaller than a node are normally placed on the left, while larger values are placed on the right.

A balanced tree supports efficient searching, insertion and deletion. However, an unbalanced tree can begin to behave like a linked list, reducing performance from logarithmic to linear time.

Graphs

A graph represents relationships using vertices and edges. A graph may be directed or undirected, and its edges may contain weights such as distance, time or financial cost.

Graphs are used in social networks, route planning, recommendation systems, dependency management and computer networks. They are flexible, but graph algorithms can become computationally expensive on large or highly connected datasets.

2. Searching and Sorting Algorithms

Linear Search

Linear search checks items one at a time until the target is found or the collection ends. It works with sorted and unsorted data and is simple to implement.

Its worst-case time complexity is O(n), because every item may need to be checked. It remains appropriate for small collections or data that is searched infrequently.

Binary Search

Binary search repeatedly checks the middle item of a sorted collection. It removes half of the remaining search area after each comparison.

Its time complexity is O(log n), making it much more efficient for large datasets. However, the collection must be sorted and should support efficient access to its middle items. The cost of creating and maintaining that order must therefore be included when deciding whether binary search is appropriate (Cormen et al., 2022).

Merge Sort

Merge sort uses a divide-and-conquer approach. It divides data into smaller sections, sorts those sections and merges them back together.

Its time complexity is O(n log n) in the best, average and worst cases. It is stable and predictable, but it usually requires additional memory for the merging process.

Quick Sort

Quick sort selects a pivot and partitions values so that smaller values appear before it and larger values appear after it. The same process is then applied recursively.

Average performance is O(n log n), and it often performs well in practice. Its worst case is O(n²), although a suitable pivot-selection strategy reduces the likelihood of this occurring.

3. Algorithmic Efficiency

Time Complexity

Time complexity describes how the number of operations grows as the input size increases. It does not normally measure exact execution time because that depends on hardware, programming language and implementation.

Space Complexity

Space complexity describes how memory requirements grow with the input size. An algorithm may complete quickly but require a large amount of additional memory.

Big-O Notation

Big-O notation describes an upper bound on an algorithm's growth rate. It allows algorithms to be compared without depending on a particular computer.

  • O(1): constant growth
  • O(log n): logarithmic growth
  • O(n): linear growth
  • O(n log n): linearithmic growth
  • O(n²): quadratic growth

Big-O is useful, but it is not a complete measurement. Real performance also depends on constants, memory access, input distribution and the size of the dataset. Consequently, complexity analysis should guide design decisions rather than replace benchmarking and profiling with representative data.

4. Data Storage Formats

CSV

CSV stores tabular data as plain text, with each line representing a row and delimiters separating values. It is simple, compact and widely supported.

CSV does not reliably preserve data types, nested structures or relationships. Different delimiter and character-encoding conventions can also create compatibility problems.

JSON

JSON represents information using objects, arrays, numbers, strings, Boolean values and null values. It is widely used by web APIs because it maps naturally to structures used in programming languages.

JSON supports nested data but is more verbose than CSV for simple tables. It also does not provide the query, validation and transaction capabilities of a database.

5. Databases

Relational Databases

Relational databases organise data into tables with rows and columns. Relationships are created using primary and foreign keys. SQL is used to define, query and modify the data.

Relational databases are appropriate where data requires a clear structure, strong consistency and reliable transactions. Examples include banking, payroll and booking systems.

NoSQL Databases

NoSQL refers to non-relational approaches such as document, key-value, column-family and graph databases. These systems often support flexible data structures and horizontal scaling.

NoSQL can be useful for rapidly changing data, distributed applications and high-volume workloads. However, weaker schema control can move validation responsibilities into application code.

6. Data Processing and Analytics

pandas

pandas provides DataFrame and Series structures for loading, cleaning, transforming and analysing structured data. Its official user guide covers missing data, grouping, reshaping and input/output operations (pandas Development Team, 2026). It is particularly useful for CSV files and database query results, although memory use can become restrictive for datasets that are much larger than available RAM.

NumPy

NumPy provides efficient multidimensional arrays and numerical operations. Its vectorised operations avoid many explicit Python loops and can process numerical data efficiently (NumPy Developers, 2026). However, vectorisation may create temporary arrays, so improved execution speed does not always mean reduced memory use.

Matplotlib and Seaborn

Matplotlib provides detailed control over charts and visualisations. Seaborn builds on Matplotlib and offers higher-level functions for statistical visualisation.

Visualisations should communicate a specific finding. Incorrect scales, excessive decoration and unsuitable chart types can misrepresent data rather than clarify it.

Overall Evaluation

The most appropriate solution depends on the operations a system performs most frequently. Data structures, algorithms, storage formats and databases should therefore be selected together rather than as isolated technical decisions.
