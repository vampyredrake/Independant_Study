Introduction

Modern organisations depend on networks and cloud platforms to deliver applications, store information and support communication. These technologies create significant operational benefits, but they also expand the number of systems, identities and communication paths that must be protected.

Networking, cloud computing and cybersecurity should not be treated as separate subjects. Security controls depend on understanding how information moves through a network, where services are hosted and which organisation is responsible for each technical layer. This systems view is consistent with the NIST Cybersecurity Framework, which treats governance, protection, detection, response and recovery as related risk-management activities (National Institute of Standards and Technology, 2024).

1. Network Models and Transport Protocols

The OSI Seven-Layer Model

The Open Systems Interconnection model divides network communication into seven conceptual layers. Each layer performs a particular function and provides services to the layer above it.

The model is valuable for explaining network behaviour and troubleshooting. For example, a broken cable is a physical-layer problem, while an incorrect IP route is a network-layer problem. Modern protocols do not always fit neatly into one layer, so the model should be treated as a conceptual framework rather than an exact implementation (Kurose and Ross, 2021).

1. Physical

Transmits bits using electrical, optical or wireless signals.

2. Data Link

Transfers frames across a local network and uses hardware addresses.

3. Network

Provides logical addressing and routing between networks.

4. Transport

Manages end-to-end communication, reliability and ports.

5. Session

Establishes, maintains and ends communication sessions.

6. Presentation

Handles data representation, encryption and compression.

7. Application

Provides network services used by applications and users.

TCP/IP Protocol Suite

TCP/IP is the practical protocol suite used by the internet. It is commonly represented using four layers: application, transport, internet and network access.

TCP/IP Layer Related OSI Layers Examples
Application Application, presentation and session HTTP, HTTPS, DNS, SMTP and SSH
Transport Transport TCP and UDP
Internet Network IPv4, IPv6 and ICMP
Network access Data link and physical Ethernet and Wi-Fi

TCP

Transmission Control Protocol provides reliable, connection-oriented communication. It uses sequencing, acknowledgements and retransmission to help data arrive correctly and in order.

UDP

User Datagram Protocol is connectionless and has lower overhead. It is useful where low delay is more important than guaranteed delivery, such as voice calls, streaming and online games.

Key takeaway

The OSI model supports explanation and troubleshooting, while TCP/IP describes the protocol suite used by real internet systems.

2. IPv4, IPv6 and Subnetting

IPv4

IPv4 uses 32-bit addresses, normally written as four decimal values separated by full stops.

Example: 192.168.1.20

Its address space provides approximately 4.3 billion possible addresses. NAT extends the usable life of IPv4 by allowing private devices to share public addresses.

IPv6

IPv6 uses 128-bit addresses written as hexadecimal groups separated by colons.

Example: 

2001:db8:85a3::8a2e:370:7334

IPv6 provides a vastly larger address space and supports more efficient address assignment (Internet Engineering Task Force, 2017).

IP Addressing

An IP address contains a network portion and a host portion. The subnet mask or prefix length determines which bits identify the network.

The address 192.168.10.25/24 uses the first 24 bits for the network. The remaining eight bits identify hosts within that network. 

Network address:   192.168.10.0
Usable range:      192.168.10.1 - 192.168.10.254
Broadcast address: 192.168.10.255

Subnetting

Subnetting divides a larger address range into smaller networks. It can reduce broadcast traffic, organise departments and support security segmentation. 

192.168.10.0/26
192.168.10.64/26
192.168.10.128/26
192.168.10.192/26

Each subnet contains 64 total addresses. In a standard IPv4 subnet, the network and broadcast addresses cannot normally be assigned to hosts, leaving 62 usable host addresses.

Key takeaway

IPv6 addresses exhaustion, but it does not remove the need for firewalls, access control, monitoring or secure configuration.

3. Cloud Computing and Virtualisation

Cloud-Computing Concepts

Cloud computing provides shared computing resources over a network. These resources may include servers, storage, databases, networking, applications and development platforms.

NIST identifies on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service as defining characteristics of cloud computing (Mell and Grance, 2011).

IaaS

Infrastructure as a Service provides virtual machines, storage and networking.

The provider manages physical infrastructure, while the customer normally manages operating systems, applications, data and security settings.

PaaS

Platform as a Service provides an application platform, runtime and managed infrastructure.

Development teams deploy code without managing every server or operating-system component.

SaaS

Software as a Service provides a complete application accessed through a browser or client.

The customer remains responsible for users, permissions, configuration and data-handling decisions.

Serverless Architecture

Serverless computing allows developers to deploy functions or managed services without directly managing servers. Servers still exist, but the provider manages provisioning, scaling and much of the infrastructure.

Advantages

  • automatic scaling;
  • event-driven execution;
  • reduced server management;
  • usage-based charging.

Limitations

  • cold-start delay;
  • execution-time restrictions;
  • monitoring complexity;
  • vendor lock-in.

Virtualisation and Hypervisors

Virtualisation allows one physical computer to operate multiple isolated virtual machines. Each virtual machine can have its own operating system and allocated resources.

Hypervisor Type Operation Typical Use
Type 1 Runs directly on hardware Servers, data centres and cloud platforms
Type 2 Runs inside a host operating system Development, testing and desktop use

Key takeaway

Cloud computing transfers some operational work to a provider, but it does not transfer responsibility for data, identity or secure configuration.

4. Threat Actors and Attack Vectors

Threat Actors

A threat actor is an individual or group capable of causing harm to a system. Threat actors differ in motivation, resources and technical skill.

Cybercriminals

Commonly motivated by financial gain.

Nation-state groups

May conduct espionage, disruption or political operations.

Insiders

May act maliciously or cause accidental harm.

Hacktivists

Normally act in support of an ideological or political cause.

Competitors

May seek commercial intelligence or strategic advantage.

Common Attack Vectors

DDoS

A distributed denial-of-service attack uses traffic from multiple systems to exhaust bandwidth, processing capacity or application resources.

Controls include rate limiting, filtering, load balancing, additional capacity and specialist protection services.

SQL Injection

SQL injection occurs when untrusted input is interpreted as part of a database command.

Parameterised queries are the primary control, supported by validation and least-privilege database accounts (OWASP Foundation, 2026a).

Cross-Site Scripting

XSS occurs when attacker-controlled content is executed in another user's browser.

Controls include output encoding, safe templating, sanitisation and Content Security Policy (OWASP Foundation, 2026b).

Phishing

Phishing uses deceptive messages or websites to persuade users to reveal information or approve harmful actions.

Controls include phishing-resistant authentication, email filtering, domain protection and verification procedures.

Key takeaway

Effective defence requires both technical controls and organisational processes because attackers may target systems, identities or human decision-making.

5. Information-Security Principles

Confidentiality

Protects information from unauthorised disclosure.

  • encryption;
  • authentication;
  • access control;
  • data classification;
  • least privilege.

Integrity

Protects information from unauthorised or accidental modification.

  • hashes;
  • digital signatures;
  • validation;
  • audit logs;
  • change control.

Availability

Ensures authorised users can access systems and information when required.

  • backups;
  • redundancy;
  • fault tolerance;
  • monitoring;
  • incident response.

Key takeaway

Security controls must balance confidentiality, integrity and availability rather than optimising one principle while ignoring the others.

6. Cryptography and TLS

Symmetric Encryption

Uses the same secret key to encrypt and decrypt information. It is efficient and suitable for large amounts of data.

Its main challenge is secure key distribution.

Asymmetric Encryption

Uses a public key and a private key. It supports encryption, digital signatures and secure key establishment.

It is more computationally expensive than symmetric encryption.

Hashing

Converts input into a fixed-length digest. Hashing is one-way and is not encryption.

It supports integrity checking, signatures and password storage.

AES

The Advanced Encryption Standard is a widely used symmetric block cipher standardised by NIST. AES supports key lengths of 128, 192 and 256 bits (National Institute of Standards and Technology, 2001).

RSA and Digital Signatures

RSA is an asymmetric cryptographic algorithm used for encryption and digital signatures. It is normally used for smaller values, signatures or key establishment rather than bulk data encryption.

TLS

Transport Layer Security protects communication between applications. TLS 1.3 provides confidentiality, integrity and server authentication (Internet Engineering Task Force, 2018).

During a TLS connection, asymmetric cryptography and certificates help authenticate the server and establish session secrets. Symmetric encryption is then used for the main data transfer because it is more efficient.

Key takeaway

Secure cryptography depends on correct key management, configuration and endpoint security, not merely on selecting a strong algorithm.

7. Cloud Access Control and Security

Shared Responsibility

Cloud security follows a shared-responsibility model. The provider protects the underlying service, but the customer remains responsible for account security, access permissions, data handling and many configuration decisions.

The exact division depends on the service model. A customer using IaaS has more technical responsibility than a customer using SaaS.

Identity and Access Management

Cloud identity and access management controls which users, applications and services may access resources. Policies should follow least privilege.

  • Multifactor authentication
  • Role-based access control
  • Conditional access policies
  • Short-lived credentials
  • Privileged-access management
  • Regular access reviews
  • Logging and alerting
  • Separation of development and production accounts

Cloud Misconfiguration

Cloud incidents frequently involve valid services that have been configured insecurely. Examples include public storage, unrestricted firewall rules, excessive permissions and exposed management interfaces.

Infrastructure as code, automated policy checks, configuration baselines and continuous monitoring can reduce these risks. Automation must still be reviewed because an incorrect template can reproduce the same weakness across many environments.

Zero Trust

Zero trust avoids treating network location as sufficient evidence of trust. Each access request should be evaluated using identity, device state, permissions, resource sensitivity and current risk.

Key takeaway

Cloud security depends heavily on identity, least privilege, secure configuration and continuous verification.

Overall Evaluation

Cloud platforms and modern networks increase flexibility, but they also make identity, configuration and communication security more important. Effective security requires layered controls across users, applications, networks, data and cloud-management systems.
