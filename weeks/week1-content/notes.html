Introduction

Modern web applications depend on several technical layers working together. The visible interface is only one part of the system. Semantic structure, responsive presentation, JavaScript behaviour, network communication and software-design principles all affect whether an application is accessible, maintainable and capable of supporting growth.

These notes organise the Week 1 material into four connected areas. This structure demonstrates how front-end technologies, programming practices and web infrastructure contribute to the operation of a complete software system.

Front-End Development JavaScript and Typing Web Infrastructure Programming Principles
1. Front-End Development

HTML5 and Semantic Markup

HTML5 provides the structural foundation of a webpage. Its purpose is not limited to displaying text and images. Semantic elements describe the role of content and create a document structure that is easier for developers, browsers and assistive technologies to interpret (WHATWG, 2026).

Semantic Structure

Elements such as <header>, <nav>, <main>, <article> and <footer> communicate the purpose of content.

Generic Structure

A page built mainly from <div> elements may look correct, but communicates less meaning to developers and assistive technologies.

Accessibility limitation

Semantic markup supports accessibility, but it does not make a page accessible by itself. Keyboard operation, meaningful labels, logical focus order and understandable content are still required (World Wide Web Consortium, 2023).

CSS Grid and Flexbox

CSS controls the visual presentation and layout of web content. Grid and Flexbox solve related but different layout problems.

Flexbox

Flexbox is primarily one-dimensional. It arranges elements along a row or column and is suitable for navigation bars, button groups and component alignment.

CSS Grid

Grid is two-dimensional because it manages rows and columns together. It is suitable for dashboards, galleries and larger page structures.

Layout Tool Primary Dimension Typical Use Potential Limitation
Flexbox One-dimensional Navigation, alignment and components Less suitable for complex row-and-column layouts
CSS Grid Two-dimensional Page layouts, galleries and dashboards Can be unnecessarily complex for simple alignment

UI, UX and Accessibility

User Interface

Concerns visible controls, typography, spacing, colour and layout.

User Experience

Concerns whether tasks are understandable, efficient, predictable and appropriately supported by feedback.

Accessibility

Reduces barriers through meaningful headings, keyboard access, labelled controls, alternative text and suitable contrast.

A visually attractive interface can still provide poor user experience when navigation is confusing or the system fails to confirm an action. Accessibility should therefore be considered throughout design, implementation and testing rather than added at the end.

Automated tools can identify some technical failures, but human evaluation remains necessary because software cannot always determine whether content is understandable or practical to use (World Wide Web Consortium, 2023).

Professional relevance

Semantic HTML, responsive CSS and accessible interaction improve maintainability and allow a wider range of users to complete tasks successfully.

Key takeaway

Front-end quality depends on structure, presentation and usability working together. Visual appearance alone is not sufficient.

2. JavaScript, ES6+ and Data Typing

JavaScript and ES6+

JavaScript supplies behaviour and interaction within modern web applications. It can validate forms, update page content, communicate with APIs and manage user events.

ES6 and later versions introduced features that make larger programs easier to organise. These include let, const, arrow functions, classes, modules, destructuring and template literals.

const

Used when the variable binding should not be reassigned.

let

Used when the stored value needs to change during execution.

var

Older declaration form with function scope and behaviour that can be less predictable in larger programs.

Asynchronous Programming

Web applications often wait for external operations such as API requests. Blocking the entire interface during these operations would make the application appear unresponsive.

Promises and async/await allow delayed results to be managed while other work continues. Asynchronous syntax improves readability, but it does not remove the possibility of failed, delayed or malformed responses.

Dynamic and Static Type Checking

Dynamic Typing

JavaScript variables can hold values of different types during execution. This can support rapid development, but some mistakes only appear at runtime.

Static Type Checking

Java, C# and TypeScript apply type checks before execution. This can reveal mismatches earlier and improve communication within large codebases.

Static type checking does not remove the need for testing and code review. Comparative research has found that TypeScript projects do not automatically have fewer defects or shorter bug-resolution times than JavaScript projects (Bogner and Merkel, 2022).

Professional relevance

The choice between dynamic and static type checking should reflect project scale, technical risk, maintenance requirements and team practices.

Key takeaway

Modern JavaScript improves code organisation, but robust applications still require validation, error handling, testing and deliberate type management.

3. Web Infrastructure

Client–Server Architecture

Most web applications use a client–server model. The client is commonly a browser or mobile application. It displays the interface, collects user input and sends requests.

The server receives requests, applies business rules, accesses stored information and returns a response. Separating these responsibilities allows client, server and database components to be developed independently. However, distributed components also introduce network latency and additional points of failure (Kurose and Ross, 2021).

From Domain Name to Webpage

DNS

The Domain Name System translates a human-readable domain name into an IP address. A browser first checks whether the address is cached. When it is not, a DNS resolver locates the appropriate record (Kurose and Ross, 2021).

DNS is therefore an essential stage before a browser can connect to the intended server and send an HTTP request.

HTTP and HTTPS

HTTP

Defines request and response semantics, including methods, status codes, headers and caching behaviour (Fielding, Nottingham and Reschke, 2022).

HTTPS

Uses TLS to protect HTTP communication in transit, preserve integrity and help authenticate the server.

Status Code Category Meaning
200 Success The request was processed successfully.
404 Client error The requested resource could not be found.
500 Server error The server encountered an unexpected problem.

Encryption significantly reduces the risk of interception. However, secure deployment still depends on current protocol versions, appropriate configuration and effective certificate management (Sheffer, Saint-Andre and Fossati, 2022).

Hosting and Web Servers

A web server such as Apache, Nginx or Microsoft IIS can deliver static resources and route requests to application code.

Shared Hosting

Relatively inexpensive and simple, but offers limited administrative control and shared resources.

Virtual Private Server

Provides greater control and flexibility, but requires operating-system administration, patching and security management.

Cloud Hosting

Supports elasticity and managed services, but can introduce cost complexity, data-transfer charges and provider dependency.

Ofcom (2023) identified barriers to switching and multi-cloud use in the UK cloud-infrastructure market. Scalability should therefore be assessed alongside cost, contractual constraints and commercial dependency.

Scaling may involve load balancing, caching, multiple application instances and database optimisation. Unnecessary infrastructure can nevertheless make a small system harder to operate and maintain.

Professional relevance

Developers who understand DNS, HTTP, TLS, hosting and server architecture can diagnose performance, availability and security issues more effectively.

Key takeaway

A webpage depends on a chain of infrastructure services. Failure at DNS, network, server, application or database level can prevent the final interface from working.

4. Advanced Programming Principles

Object-Oriented Programming

Object-oriented programming organises software around objects containing state and behaviour. A class acts as a template from which objects can be created.

Encapsulation

Controls access to internal state through defined methods or properties.

Inheritance

Allows one class to reuse or extend behaviour defined by another class.

Polymorphism

Allows different objects to respond through a common interface.

Composition

Builds behaviour by combining objects rather than creating deep inheritance hierarchies.

OOP can reduce duplication and improve organisation, but it can also create unnecessary complexity. Deep inheritance structures are difficult to understand and maintain. Composition may be preferable when an object only needs to use another object's behaviour (Albahari, 2023).

Recursion

Recursion occurs when a function calls itself. It is useful for problems containing smaller versions of the same problem, including tree traversal and directory processing.

Recursion

Can express hierarchical and tree-shaped problems clearly, but creates an additional stack frame for each call.

Iteration

Often uses less memory for straightforward repetition because it avoids repeated function calls.

Concurrency and Multithreading

Concurrency concerns the management of tasks whose execution overlaps. Multithreading is one technique for supporting concurrency by using several threads within the same process.

Potential Benefits

  • improved responsiveness;
  • higher server throughput;
  • better use of multi-core processors;
  • overlapping input/output operations.

Potential Risks

  • race conditions;
  • deadlocks;
  • shared-state corruption;
  • difficult testing and debugging.

Concurrency does not necessarily mean that tasks execute at precisely the same moment. A single processor can switch rapidly between tasks, whereas a multi-core processor may execute some tasks in parallel.

The possible performance benefit must be balanced against additional design and testing complexity (Albahari, 2023).

Professional relevance

Advanced programming techniques should solve a genuine design, maintainability or performance problem. They should not be introduced only to make a project appear more technically complex.

Key takeaway

Abstraction, recursion and concurrency are useful when matched to an appropriate problem. Poorly chosen complexity can make software less reliable rather than more advanced.

Overall Evaluation

Web development is a connected system rather than a collection of unrelated technologies. Semantic HTML and accessible user experience improve the client interface. JavaScript supports interaction, DNS and HTTPS deliver requests, servers process application logic, and programming principles influence maintainability and scalability.

The effectiveness of the final system depends on these parts working together. A technically sophisticated implementation can still fail when its interface is inaccessible, its network communication is insecure or its software structure is unnecessarily complex.
