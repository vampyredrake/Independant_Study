Introduction

Modern organisations depend on networks and cloud platforms to deliver applications, store information and support communication. These technologies create significant operational benefits, but they also expand the number of systems, identities and communication paths that must be protected.

Networking, cloud computing and cybersecurity should not be treated as separate subjects. Security controls depend on understanding how information moves through a network, where services are hosted and which organisation is responsible for each technical layer. This systems view is consistent with the NIST Cybersecurity Framework, which treats governance, protection, detection, response and recovery as related risk-management activities (National Institute of Standards and Technology, 2024).

1. Network Models

The OSI Seven-Layer Model

The Open Systems Interconnection model divides network communication into seven conceptual layers. Each layer performs a particular function and provides services to the layer above it.

The model is valuable for explaining network behaviour and troubleshooting. For example, a broken cable is a physical-layer problem, while an incorrect IP route is a network-layer problem. However, modern protocols do not always fit neatly into one OSI layer, so the model should be treated as a conceptual framework rather than an exact implementation (Kurose and Ross, 2021).

  1. Physical: transmits bits using electrical, optical or wireless signals.
  2. Data Link: transfers frames across a local network and uses hardware addresses.
  3. Network: provides logical addressing and routing between networks.
  4. Transport: manages end-to-end communication, reliability and ports.
  5. Session: establishes, maintains and ends communication sessions.
  6. Presentation: handles data representation, encryption and compression.
  7. Application: provides network services used by applications and users.

The TCP/IP Protocol Suite

TCP/IP is the practical protocol suite used by the internet. It is commonly represented using four layers: application, transport, internet and network access.

TCP/IP Layer Related OSI Layers Examples
Application Application, presentation and session HTTP, HTTPS, DNS, SMTP and SSH
Transport Transport TCP and UDP
Internet Network IPv4, IPv6 and ICMP
Network access Data link and physical Ethernet and Wi-Fi

Transmission Control Protocol provides reliable, connection-oriented communication. It uses sequencing, acknowledgements and retransmission to increase the likelihood that data arrives correctly and in order.

User Datagram Protocol is connectionless and has lower overhead. It is useful where low delay is more important than guaranteed delivery, such as voice calls, video streaming and some online games.

2. IPv4, IPv6 and Subnetting

IPv4

Internet Protocol version 4 uses 32-bit addresses, normally written as four decimal values separated by full stops. An example is 192.168.1.20.

A 32-bit address space provides approximately 4.3 billion possible addresses. The practical number available for public use is lower because some ranges are reserved. Network Address Translation has extended the usable life of IPv4 by allowing many private devices to share one or more public addresses.

IPv6

Internet Protocol version 6 uses 128-bit addresses, written as hexadecimal groups separated by colons. An example is: 

2001:0db8:85a3:0000:0000:8a2e:0370:7334

Repeated zero groups can be compressed: 

2001:db8:85a3::8a2e:370:7334

IPv6 provides a vastly larger address space and supports more efficient address assignment (Internet Engineering Task Force, 2017). It does not make a network secure automatically. Firewalls, access controls and secure configuration are still required, and organisations must avoid assuming that address-space size is itself a security control.

IP Addressing

An IP address contains a network portion and a host portion. The subnet mask or prefix length determines which bits identify the network.

The address 192.168.10.25/24 uses the first 24 bits for the network. The remaining eight bits identify hosts within that network. 

Network address:   192.168.10.0
Usable range:      192.168.10.1 - 192.168.10.254
Broadcast address: 192.168.10.255

Subnetting

Subnetting divides a larger address range into smaller networks. It can reduce broadcast traffic, organise departments and support security segmentation.

A /24 network divided into four equal subnets produces four /26 networks: 

192.168.10.0/26
192.168.10.64/26
192.168.10.128/26
192.168.10.192/26

Each subnet contains 64 total addresses. In a standard IPv4 subnet, the network and broadcast addresses cannot normally be assigned to hosts, leaving 62 usable host addresses.

3. Cloud Computing

Cloud-Computing Concepts

Cloud computing provides shared computing resources over a network. These resources may include servers, storage, databases, networking, applications and development platforms.

Cloud services are normally designed for on-demand access, rapid scaling and measured usage. NIST identifies on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service as the defining characteristics of cloud computing (Mell and Grance, 2011). Organisations can obtain infrastructure without purchasing and maintaining every physical component themselves, although responsibility for data, identities and configuration is not transferred automatically to the provider.

Cloud deployment models include public cloud, private cloud, hybrid cloud and multi-cloud. A public cloud uses shared provider infrastructure. A private cloud is dedicated to one organisation. A hybrid model combines local or private systems with public-cloud services.

Infrastructure as a Service

IaaS provides virtual machines, storage and networking. The provider manages the physical infrastructure, while the customer normally manages operating systems, applications, data and many security settings.

Platform as a Service

PaaS provides an application platform, runtime and managed infrastructure. Development teams deploy code without managing every server or operating-system component.

Software as a Service

SaaS provides a complete application accessed through a browser or client. The provider manages most of the application stack, while the customer manages users, permissions, configuration and data-handling decisions.

Serverless Architecture

Serverless computing allows developers to deploy functions or managed services without directly managing servers. The term does not mean that servers do not exist. It means the provider manages provisioning, scaling and much of the infrastructure.

Serverless services are useful for event-driven tasks, APIs and workloads with irregular demand. Limitations can include execution-time restrictions, cold-start delay, monitoring complexity and vendor lock-in.

Virtualisation and Hypervisors

Virtualisation allows one physical computer to operate multiple isolated virtual machines. Each virtual machine can have its own operating system and allocated resources.

A Type 1 hypervisor runs directly on physical hardware. This model is common in data centres. A Type 2 hypervisor runs on top of a host operating system and is often used for desktop testing or development.

Hypervisor Type Operation Typical Use
Type 1 Runs directly on hardware Servers, data centres and cloud platforms
Type 2 Runs inside a host operating system Development, testing and desktop use

4. Threat Actors and Attack Vectors

Threat Actors

A threat actor is an individual or group capable of causing harm to a system. Threat actors differ in motivation, resources and technical skill.

  • Cybercriminals: commonly motivated by financial gain.
  • Nation-state groups: may conduct espionage, disruption or political operations.
  • Insiders: may act maliciously or cause accidental harm.
  • Hacktivists: normally act in support of an ideological or political cause.
  • Competitors: may seek commercial intelligence or strategic advantage.

Attack Vectors

An attack vector is the path or method used to compromise a system. Examples include email, exposed remote services, stolen credentials, vulnerable web applications, malicious software updates and misconfigured cloud storage.

Denial of Service and Distributed Denial of Service

A denial-of-service attack attempts to make a system unavailable by exhausting bandwidth, processing capacity, memory or application resources.

A distributed denial-of-service attack uses traffic from multiple systems, often compromised devices in a botnet. Distribution makes the attack more difficult to block because the traffic does not come from one source.

Mitigations include traffic filtering, rate limiting, content delivery networks, load balancing, additional capacity and specialist DDoS protection services.

SQL Injection

SQL injection occurs when untrusted input is interpreted as part of a database command. An attacker may retrieve, modify or delete information, depending on the database account's permissions.

Parameterised queries are the primary control because they separate data from SQL instructions. Additional controls include allow-list input validation, least-privilege database accounts and secure error handling (OWASP Foundation, 2026a). Input validation alone is insufficient because syntactically valid input may still alter a query when unsafe string construction is used.

Cross-Site Scripting

Cross-site scripting occurs when attacker-controlled content is executed in another user's browser. It can be reflected, stored or caused by unsafe client-side code.

XSS may allow account impersonation, page modification, false forms or unauthorised actions. Controls include context-appropriate output encoding, safe templating, appropriate sanitisation and a restrictive Content Security Policy (OWASP Foundation, 2026b). Content Security Policy is a defence-in-depth measure rather than a substitute for correct output handling.

Phishing

Phishing uses deceptive messages or websites to persuade users to reveal information, approve access or execute a harmful action. Modern phishing may target passwords, multifactor authentication prompts, OAuth permissions or financial processes.

Technical controls should support user awareness. Effective measures include phishing-resistant authentication, email filtering, domain protection, restricted application consent and procedures for verifying financial requests.

5. Information-Security Principles

Confidentiality

Confidentiality protects information from unauthorised disclosure. Controls include encryption, authentication, access control, data classification and least privilege.

Integrity

Integrity protects information from unauthorised or accidental modification. Controls include hashes, digital signatures, validation, audit logs and change control.

Availability

Availability ensures that authorised users can access systems and information when required. Controls include backups, redundancy, fault tolerance, monitoring, capacity planning and incident response.

6. Cryptography

Symmetric Encryption

Symmetric encryption uses the same secret key to encrypt and decrypt information. It is efficient and suitable for protecting large amounts of data.

The main challenge is secure key distribution. Anyone who obtains the key may be able to decrypt the protected information.

AES

The Advanced Encryption Standard is a widely used symmetric block cipher standardised by NIST. AES supports key lengths of 128, 192 and 256 bits (National Institute of Standards and Technology, 2001).

Encryption strength depends on more than the algorithm. Secure modes of operation, random nonces, authentication and safe key storage are also required.

Asymmetric Encryption

Asymmetric cryptography uses a public key and a private key. Information encrypted for a recipient can be protected using the recipient's public key and recovered using the corresponding private key.

Asymmetric methods can also support digital signatures. A private key is used to create a signature, while the public key is used to verify it.

RSA

RSA is an asymmetric cryptographic algorithm used for encryption and digital signatures. It is computationally more expensive than symmetric encryption and is therefore normally used for smaller values, signatures or key establishment rather than bulk data encryption.

Hashing

A cryptographic hash function converts input into a fixed-length digest. A small change to the input should produce a significantly different digest.

Hashing is one-way and is not encryption. It supports integrity checking, digital signatures and secure password storage. Passwords should be processed using a purpose-designed password-hashing function with unique salts rather than a fast general-purpose hash alone.

SSL and TLS

Transport Layer Security protects communication between applications. TLS 1.3 provides confidentiality, integrity and server authentication, while client authentication may also be configured (Internet Engineering Task Force, 2018). Its protection is end-to-end only between the TLS endpoints; compromised endpoints can still expose plaintext data.

SSL is obsolete and has been replaced by TLS. The term SSL is still sometimes used informally, but secure systems should use supported TLS versions and configurations.

During a TLS connection, asymmetric cryptography and certificates help authenticate the server and establish session secrets. Symmetric encryption is then used for the main data transfer because it is more efficient.

7. Cloud Access Control and Security

Shared Responsibility

Cloud security follows a shared-responsibility model. The provider protects the underlying service, but the customer remains responsible for areas such as account security, access permissions, data handling and many configuration decisions.

The exact division depends on the service model. A customer using IaaS has more technical responsibility than a customer using SaaS.

Identity and Access Management

Cloud identity and access management controls which users, applications and services may access resources. Policies should follow least privilege so that each identity has only the permissions required for its role.

Effective controls include:

  • multifactor authentication;
  • role-based access control;
  • conditional access policies;
  • short-lived credentials;
  • privileged-access management;
  • regular access reviews;
  • logging and alerting;
  • separation of development and production accounts.

Cloud Misconfiguration

Cloud incidents frequently involve valid services that have been configured insecurely. Examples include public storage, unrestricted firewall rules, excessive permissions and exposed management interfaces.

Infrastructure as code, automated policy checks, configuration baselines and continuous monitoring can reduce these risks. Automation must still be reviewed, because an incorrect template can reproduce the same weakness across many environments.

Zero-Trust Principles

Zero trust avoids treating network location as sufficient evidence of trust. Each access request should be evaluated using identity, device state, permissions, resource sensitivity and current risk.

Zero trust is not one product. It is an architectural approach involving identity controls, segmentation, continuous verification, monitoring and limited access.

Overall Evaluation

Cloud platforms and modern networks increase flexibility, but they also make identity, configuration and communication security more important. Effective security requires layered controls across users, applications, networks, data and cloud-management systems.
