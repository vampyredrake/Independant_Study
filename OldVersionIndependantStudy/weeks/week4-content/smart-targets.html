Purpose of the Targets

SMART targets are Specific, Measurable, Achievable, Relevant and Time-bound. The following three targets respond directly to the weaknesses and opportunities identified in my SWOT analysis.

Target 1: Complete and Quality-Assure the Portfolio

Specific: Complete all outstanding portfolio pages and conduct a final review of content, navigation, accessibility, spelling and referencing.

Measurable: Every required page will contain completed content, all internal links will work, images will have appropriate alternative text and the project will contain no known missing files.

Achievable: The weekly content is already substantially developed, so the remaining work can be completed using a structured checklist.

Relevant: This directly supports the quality and reliability of the final Level 5 portfolio submission.

Time-bound: Complete the final quality-assurance review before the planned September submission date.

Target 2: Improve Practical Web Development Skills

Specific: Build one small interactive web application using semantic HTML, CSS and JavaScript.

Measurable: The application will include at least one form, input validation, dynamic page behaviour and a documented test table.

Achievable: The scope will be limited to a manageable application such as a task tracker, quiz or study planner.

Relevant: This will strengthen the practical evidence supporting my existing front-end development knowledge.

Time-bound: Complete and document the application within eight weeks of submitting the portfolio.

Target 3: Improve Project Planning and Testing

Specific: Use a project plan, risk register and formal testing checklist for my next substantial computing project.

Measurable: The documentation will include milestones, deadlines, identified risks, mitigation actions and recorded test outcomes.

Achievable: Templates can be prepared in advance and updated throughout the project.

Relevant: This addresses weaknesses in time management, scope control and systematic quality assurance.

Time-bound: Apply the documentation from the first week of the next assessed project.

Review Process

Progress should be reviewed monthly. Each review should record whether the target is on schedule, what evidence has been produced and whether any justified adjustment is necessary. Targets should not be changed merely because progress becomes difficult.

Together, these targets prioritise completion of the current portfolio while supporting longer-term development in practical programming, project management and quality assurance.
